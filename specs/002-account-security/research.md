# Phase 0 Research: Account Security & Profile

**Feature**: [spec.md](spec.md) · **Plan**: [plan.md](plan.md) · **Date**: 2026-09-28

Builds on spec 001's decisions (R-01 … R-15 in `specs/001-design-system-auth/research.md`); only new or changed decisions are recorded here.

---

## R-01 On-device database

- **Decision**: Room Kotlin Multiplatform `2.8.5` with the bundled SQLite driver (`androidx.sqlite:sqlite-bundled` `2.7.1`), code generated by KSP `2.3.12` (KSP2, independent of the Kotlin version). One `AppDatabase` in `core.database`, built by an `expect fun databaseBuilder()` per platform (Android: app database path; iOS: Documents directory), `setDriver(BundledSQLiteDriver())`, `setQueryCoroutineContext(Dispatchers.IO)`. Schema exported to `shared/schemas/` via the Room Gradle plugin; version 1, no migrations yet.
- **Rationale**: Owner decision (2026-09-28) to satisfy P-04 with a real database now, as groundwork for wallets and transactions. Room is the Jetpack-standard KMP database, supports Android and iOS from `commonMain`, and exposes `Flow` queries so screens observe the database (P-04.1). The bundled driver gives the same SQLite version on both platforms.
- **Alternatives considered**: SQLDelight (SQL-first, also KMP) — equally viable, rejected for owner preference; DataStore JSON blobs — no queries, no transactions, does not scale to transactions/wallets.
- **Dependency approval (P-14.5)**: Room runtime, Room compiler (KSP), sqlite-bundled, KSP plugin, Room Gradle plugin — approved by the owner on 2026-09-28 ("add room sqlite database").

## R-02 Sync model for Profile and Device Session

- **Decision**: No change feed exists yet in the backend contract, so "pull" is a full re-read: `GET /me` for Profile (and Account), `GET /auth/sessions?filter[state]=active` for sessions, all pages. Results are written to the database in one transaction; screens only observe the database. "Push" exists only for Profile: a local save writes a *pending edit* row beside the server copy; a `ProfileSyncer` sends `PUT /me/profile` with the whole draft and the server copy's `version`.
- **Pull never clobbers a pending edit**: pull updates the server-copy columns only; the pending edit stays until pushed or discarded (P-04.2).
- **Triggers**: after sign-in (auth state → SignedIn), on app foreground, when the account area or profile opens, immediately after a local save, and on retry after an offline failure (backoff 5 s, 15 s, 60 s, then every 5 min while the process lives). Single-flight via a `Mutex` per scope.
- **Rationale**: Meets P-04.1/2/4 with the endpoints that exist. The pull is cheap (one profile, a handful of sessions). When the user-scope change feed is specified, `ProfileRefresher`/`SessionRefresher` swap to it without touching screens.
- **Alternatives considered**: WorkManager-based background sync — Android-only and overkill for one record; syncing only while the screen is open — would lose offline edits if the person leaves the screen.

## R-03 Version conflict resolution

- **Decision**: `ProblemDetails` gains `current: JsonElement?`. On `VERSION_CONFLICT` the syncer decodes `current` as `ProfileDto`, stores it as the row's *conflict copy*, and stops. The profile screen shows pending edit vs conflict copy with "Keep mine" (rebase: pending edit's base version := conflict copy's version, conflict cleared, push again) and "Use the other device's" (server copy := conflict copy, pending edit and conflict cleared). No field merge.
- **Rationale**: API conventions §Version conflicts rules 2–3 ("client owns the merge", `current` carries present state); P-04.4 ("merge or user choice, never silent overwrite"); FR-012.
- **Alternatives considered**: Auto field-merge — rejected by the conventions (produces a row nobody wrote).

## R-04 401 handling must branch on code

- **Decision**: `ApiClient.publishEvents` publishes `ApiEvent.SessionEnded` only when the refusal code is `UNAUTHENTICATED` on a credentialed request (or a credentialed 401 whose body carries no recognisable code, i.e. `UNKNOWN`). Today it fires on any credentialed 401.
- **Rationale**: `changePassword` and `requestAccountDeletion` answer a wrong current password with **401 INVALID_CREDENTIALS** while the session is still valid; the current logic would sign the person out (FR-027). Also matches "branch on `code`, never on the status" (api-conventions; P-02).
- **Alternatives considered**: Special-casing the two endpoints via a request attribute — hides the real rule.

## R-05 Collections and paging

- **Decision**: Add `ApiClient.callPage<T>()` returning `Page<T>(items: List<T>, nextCursor: String?, hasMore: Boolean)` decoded from `Envelope<List<T>>` + `CollectionMeta(next_cursor, has_more, limit)`. `SessionRefresher` loops `cursor` until `has_more == false` (limit 50, hard stop at 20 pages), then replaces the stored list.
- **Rationale**: The list is small; fetching everything keeps the database complete so the screen needs no paging state. `next_cursor` is treated as opaque (CollectionMeta rule).
- **Alternatives considered**: Room Paging 3 + RemoteMediator — heavy for tens of rows.

## R-06 App language driven by the profile

- **Decision**: New `core.locale.AppLanguageStore` (KeyValueStore key `app_language`: `ar`|`en`|absent) exposing `StateFlow<AppLanguage?>`; `AppLanguage.effective = override ?: device language`. Compose: an `expect object LocalAppLocale` (the Compose Multiplatform documented pattern) whose Android actual sets `Locale.setDefault` and provides a `LocalConfiguration` copy with the locale, and whose iOS actual sets `NSUserDefaults["AppleLanguages"]`; `App()` wraps content in `CompositionLocalProvider(LocalAppLocale provides tag, LocalLayoutDirection provides dir)` inside `key(tag)` so resources re-resolve immediately. The HTTP `Accept-Language` header reads `AppLanguageStore.effective`, not the device locale.
- **When set**: profile pull or local save writes `profile.locale` to the store (the local save switches at once, FR-016; a conflict resolved with "Use the other device's" switches to that value). Sign-out clears it (device language again).
- **Rationale**: Works with the existing `ComponentActivity` (no AppCompat), no activity recreation, same code path on iOS.
- **Alternatives considered**: `AppCompatDelegate.setApplicationLocales` — needs AppCompatActivity and recreates the activity; Android 13 `LocaleManager` — API 33+ only (minSdk 24).

## R-07 Sign-out prerequisite and local data wipe

- **Decision**: Spec 001 US5 (tasks T105–T107: `IdentityApi.signOut`, `SignOutUseCase`, confirm sheet) is a prerequisite and is implemented as part of this feature's Phase 2 if still open. `SessionManager.signOutLocally` additionally runs every registered `UserDataCleaner` (Koin `getAll()`): the database cleaner (`clearAllTables()`) and the language cleaner. Cleaners live behind a `core` interface so `SessionManager` never depends on the account feature (P-10.6/7).
- **Rationale**: Syncable user data must not survive into the next person's session on a shared phone (P-09).

## R-08 Screens and new design-system components

- **Decision**: New components in `designsystem/component/`: `AppAlertDialog` (title, body, confirm/dismiss labels, destructive tone), `AppListItem` (headline, supporting text, optional leading icon, trailing chevron/text/custom, optional click), `AppSelectField` (read-only field that opens a picker) and `SelectionSheet` (searchable single-choice list in `AppBottomSheet`). New icons: Person, Devices, Lock, Delete, Logout, Language. Each gets a catalogue section and screenshot cases (en, ar RTL, font scale 2) — P-07, P-08, P-14.4.
- **Screens (MVI, P-16)**: Account (hub), Profile, DeviceSessions, ChangePassword, DeleteAccount; Home gains an Account entry and the pending-deletion notice with "Cancel deletion".
- **Rationale**: Confirmation dialogs (FR-004) and list rows do not exist today; pickers are needed for timezone/currency (FR-015).

## R-09 Time and currency presentation

- **Decision**: `designsystem/format/DateTimeFormat.kt`: `formatDateTime(instant, timeZoneId, language)` and `formatDate(localDate, language)` with Western digits, used for sign-in/last-used times (profile timezone, P-05) and the deletion date. Timezone picker lists `TimeZone.availableZoneIds` (kotlinx-datetime), sorted, searchable; an unknown stored zone is shown as its raw id. Currency picker lists a fixed ISO 4217 list shared with `MoneyFormatter`'s digit table (`designsystem/money/Currencies.kt`), searchable by code.
- **Rationale**: P-05 (timezone applied only when presenting), P-06.2 (Western numerals).

## R-10 Error codes and copy

- **Decision**: `ApiErrorCode` += `VERSION_CONFLICT(AfterChange)`; field code `IMMUTABLE_FIELD` mapped in `FieldProblem.Server` copy. New strings: current password incorrect, profile changed elsewhere (conflict title/body/"Keep mine"/"Use the other device's"), currency locked, waiting to sync, sessions/password/deletion copy. Change-password and deletion map `/current_password` and `/password` pointers to a `CurrentPassword` field.
- **Rationale**: FR-022/023; the backend check (2026-09-28) found both codes in the catalogue, unused by the client until now.
